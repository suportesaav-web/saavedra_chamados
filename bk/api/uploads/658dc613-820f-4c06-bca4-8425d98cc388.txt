🔴 Crítico — Segurança
1. Não existe RBAC no backend — só no frontend.
O auth.js esconde o botão "Painel Admin" e o novo_chamado.html trava o campo solicitante via JS, mas isso é só cosmético. Qualquer usuário autenticado (comum) pode chamar POST /api/usuarios, DELETE /api/cadastros/... ou GET /api/tarefas (visão total) direto via fetch ou Postman, porque nenhuma rota valida PERFIL da sessão. Isso é o ponto mais grave do sistema.
2. SENHA_HASH não é hash — é texto plano.
O login faz SENHA_HASH = :senha comparando string crua. create_usuario insere 'saavedra123' fixo, e o migracao.py insere 'migracao123' fixo. Se esse banco vazar, todas as senhas estão expostas.
3. Segredos hardcoded no código (secret_key, connection string com usuário/senha do SQL Server). Isso deveria estar em variáveis de ambiente, principalmente se esse código for pro GitHub.
4. usuario_acao_id e solicitante_id vêm do payload do cliente.
Em update_tarefa, quem fez a ação é o que o frontend manda (window.usuarioLogado.id). Um usuário mal-intencionado pode se passar por outro técnico. O ID de quem age deveria vir da sessão do servidor, nunca do body da requisição.
🟠 Bugs funcionais (achei 2 enquanto lia)
5. novo_chamado.html nunca auto-seleciona o solicitante.
jsif (window.usuarioLogado && window.usuarioLogado.USUARIO_ID) {
Mas /api/auth/me retorna id minúsculo ({"id":..., "nome":...}), não USUARIO_ID. Essa condição nunca é verdadeira.
6. Card "SLA Atenção (< 2h)" no dashboard sempre mostra undefined.
index.html lê kpis.sla_atencao, mas /api/kpis no backend nunca calcula/retorna essa chave.
🟡 Melhorias de arquitetura (não bloqueantes)

create_usuario/update_usuario recebem dict cru em vez de um BaseModel Pydantic → erro 500 feio em vez de 400 se faltar campo.
create_cadastro/delete_cadastro não validam tipo_cadastro contra TABELAS_PERMITIDAS (só get_cadastros valida) → KeyError não tratado.
auth.js usa setTimeout(carregarDashboard, 500) no index.html pra "esperar" a checagem de login — gambiarra que pode falhar em rede lenta. Melhor um await real.
